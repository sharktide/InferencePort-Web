1. Who we are and what this policy covers

InferencePort LLC (“InferencePort,” “we,” “our”) provides the InferencePort AI websites, developer console, hosted APIs and cloud features, AI Shield, managed agents, desktop application, ipx CLI and related services (together, the “Services”). This policy describes information handled when you interact with these Services. It distinguishes local-only processing from online and cloud processing; using local AI does not mean the same data handling as sending an API call to a hosted model.

For our accounts, websites, fraud prevention and billing, InferencePort generally decides why and how information is processed. Where a business customer uses our Services to process its users' content, that business may be the data controller and InferencePort may act as its processor or service provider. Third-party providers and tools may be independently responsible for information sent to them. This policy is not a substitute for their policies or for notices required of organization customers.

2. Information we collect or receive

  • Account and identity: email, account identifier, public-facing username, optional display name or profile, authentication state, linked identity-provider details, sign-in and recovery information, organization memberships and invitations. Authentication may involve Supabase, password sign-in, OAuth providers, or organization SSO. We do not need your plaintext account password to provide our API.
  • Credentials and permissions: API-key identifiers and validation records, access and refresh tokens used to authenticate clients, key names, expiry, scopes, authorized applications, organization roles, policies and settings. Treat these as secrets, including files stored on your device.
  • AI Inputs and Outputs: prompts, text, chat messages, structured decision inputs, documents, images, video, voice/audio, embedding data, AI Shield indicators, agent and tool arguments, generated results, and file or media metadata. The specific content transmitted depends on what you submit and which feature you use.
  • Saved cloud assets: synced chats and media where those features are enabled; hosted agent instructions, system prompts, connected MCP server settings and credentials, visibility settings, invitations, deployment configuration, and security/fraud-detection records where the feature requires them.
  • Usage and billing: models and API endpoints used, request times, token counts, generated media units, realtime duration, quotas, credit/rewards ledger entries, balances, payments, invoice and plan status, billing contacts, deployment charges, and limited payment method descriptions. Stripe or another checkout processor handles payment information needed for a transaction; we do not require full payment card numbers in our application.
  • Operational and security: service logs, IP address, user-agent or client software metadata, rate-limiting and authentication signals, error/diagnostic records, audit actions, security reports, feedback and communications. Organization audit logs may include an actor's email, IP address, user agent, event details and related metadata. Locally hosted proxies may instead log shortened hashes of connecting addresses on the host device.

We receive this information from you, your client application and device, your organization, identity/payment services, or third parties you connect. Please avoid sending passwords, API secrets or unnecessarily sensitive data as model inputs.

3. Local desktop app, CLI and self-hosting

Desktop app: using local Ollama models without cloud features can keep model inference on your device. The app may save chat sessions, imports, local favorites, preferences, application state and, when signed in, authentication sessions on the machine. Uninstalling the app does not necessarily erase these local data files or delete cloud accounts. Local data is subject to your device security and backup practices.

ipx CLI: the CLI may save configuration and authentication material in a local config directory, including a credentials.json file holding an API key or session tokens. It uses restrictive file modes on supported systems (such as 0600 on POSIX); this should not be treated as a guarantee that stored credentials are encrypted. Environment variables can also provide credentials. Other local CLI files can include a policy cache, server PID and server log. When you run hosted commands, their inputs and relevant files are sent to the selected cloud service.

Local servers: the app and CLI can host an Ollama-compatible server for approved users. Operators are responsible for exposing ports safely, managing allowed users and server logs, and protecting local inference traffic. Token verification can contact InferencePort's authentication service. The desktop proxy and CLI proxy have different protection capabilities; the CLI proxy does not implement the desktop proxy's optional encrypted-session handshake. Do not assume that self-hosted connections are end-to-end encrypted without securing your transport.

Importing a Hugging Face Space, external website, model, plugin or custom tool can contact its operator. Executing a tool may read local resources or contact additional services according to its permissions and implementation.

4. Cloud AI, agents, media and synchronization

Cloud services can include Lightning chat and generation; Pay-to-Go APIs for text, typed decisions, embeddings, image, audio, video, 3D and realtime; managed agents; model deployments; AI Shield; and Council MCP. To fulfill your request, we may send the relevant inputs, outputs or metadata to one or more hosting or AI-model providers. Council may involve multiple participant models, reviewers and judges. Agents may invoke user-configured MCP servers, potentially sending tool arguments or context to their operators.

Cloud inference does not necessarily create saved chat history for every request. However, cloud features can persist account and billing records, usage metadata, agent configuration and instructions, saved chat/media when enabled, generated job metadata, abuse/security signals and other data necessary for the feature. An organization's administrators may see organizational usage or audit information as permitted by their roles. An organization may direct audit events to its own configured webhook or security system.

Provider retention and training: We cannot promise zero logging, zero retention or zero model-training use by every upstream provider. Practices vary by provider, model and route, including fallback routing. Check the provider's current data-use terms and any available controls before submitting confidential or regulated material.

Depending on the selected feature and provider, vendors and integrations may include Supabase (authentication/data), Stripe (checkout/billing), Azure or other storage/infrastructure hosts, Hugging Face (models/Spaces), and model providers such as Pollinations, Experiential and other current catalog providers. This is illustrative, not a promise that all requests use these vendors or that no additional providers are used.

8. Retention, deletion and account controls

We retain information according to the feature, operational need and legal requirement, rather than a single universal deletion deadline. Account records generally persist while your account is active. Saved conversations, media, agents and configurations remain according to their feature controls until removed or their applicable retention period ends. Security/audit events, invoices and ledger entries may be retained beyond account closure for accounting, fraud prevention, compliance or disputes. Temporary caches, backups and third-party copies may expire on different schedules.

Deleting a local app, CLI installation or device file does not delete associated cloud account records, cancel a paid plan or revoke issued API keys. Deleting data from our cloud does not automatically remove third-party provider records, local backups or independently hosted server logs. Use available account and billing controls or contact us for verified access, correction and deletion requests. We may need to retain information where law or legitimate unresolved disputes require it.

9. Security measures

Controls vary across components but include authenticated routes, organization permissions, request limits, API-key controls and measures intended to minimize exposure of credentials in diagnostics. Parts of Shield use hashing and encrypted data storage. Hosted agent configuration and organization audit records may be stored separately from transient inference traffic. No environment is perfectly secure: protect your local files and tokens, review tool access, and use secure transport when exposing self-hosted services.
